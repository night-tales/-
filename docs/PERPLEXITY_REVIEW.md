## ملاحظة تنفيذية

هذا الملف يوثق مصدر التحليل فقط، ولا يعتبر نقلًا حرفيًا لمحتوى صفحة Perplexity. سيتم اعتماد الكود الفعلي في المستودع كمصدر الحقيقة عند تنفيذ الإصلاحات، مع استخدام تقرير Perplexity كمرجع مساعد.

## خطة التنفيذ

1. فحص بنية المشروع والملفات الأساسية.
2. مراجعة مشاكل البناء والاعتمادات والأمان.
3. مراجعة مسار توليد القصص والمشاهد وتشغيل المهام الخلفية.
4. مراجعة تجربة المستخدم وإدارة الأخطاء والحالات الطرفية.
5. تنفيذ الإصلاحات على Branch مستقل.
6. تشغيل الاختبارات/البناء المتاحين.
7. فتح Pull Request للمراجعة قبل الدمج في `main`.
